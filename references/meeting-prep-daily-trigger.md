# Scheduled task: meeting-prep-daily-trigger

This is the before-the-meeting counterpart to `direct-report-transcript-poll` (which handles the after-the-meeting half). Every morning, it scans the owner's calendar for today's weekly 1-on-1s, and for each one writes a prioritized Follow-ups/Growth/Achievements checklist to that person's own `Meeting Prep/To Review/` subfolder, then pings Slack. See `commands/meeting-prep-apply.md` for the other half of the loop - it reads back whatever got checked off and compiles it into the actual talking-points-and-questions list the owner takes into the meeting.

It never sends anything else automatically. It only ever produces a new checklist note under a person's own `Meeting Prep/To Review/` plus one combined Slack message and a push notification.

Registered in this vault as taskId `meeting-prep-daily-trigger`, cron `0 9 * * *` (9am daily local time, the scheduler adds a small jitter - actual next-run may land a few minutes past the hour). See that task's own `SKILL.md` (under `/Users/djordjestankovic/.claude/scheduled-tasks/meeting-prep-daily-trigger/`) for the exact registered prompt - this file documents the design, not a second copy to keep in sync by hand.

## Design notes

- **Meeting identification**: a qualifying "weekly 1-on-1" is a calendar event with exactly 2 attendees (the owner + one other person) whose title contains "weekly" case-insensitive but not "bi-weekly"/"bi weekly"/"biweekly". This vault's naming convention is `<Person> / <Owner> - Weekly` for direct reports and a similar `<Owner> / <Manager> - weekly meeting` for the owner's own manager 1:1. Group meetings with "weekly" in the title (e.g. "Competence Leads Weekly", "Nordics Engineering Leadership weekly") are excluded by the attendee-count check, not by name matching, so a newly-named group meeting doesn't slip through.
- **The owner's-own-manager exception**: the owner's manager 1:1 is not a direct report, so there's no `Knowledge Base/People/<Manager's Name>/` folder to write into. Instead, the note goes into the owner's own folder, `Knowledge Base/People/<Owner's Own Folder>/Meeting Prep/To Review/<date> - <Owner Full Name>.md`, sourced from the owner's own Profile Card/Skills Matrix rather than a direct report's - this is the owner prepping to report upward, not to manage downward.
- **Person resolution is dynamic, not a fixed roster**: unlike `direct-report-transcript-poll`'s explicit PEOPLE list, this task resolves each meeting's other attendee against `Knowledge Base/People/` recursively (fuzzy name match across every team subfolder) at run time. People move between team folders in this vault (see `_CLAUDE.md`'s Folder Map history) more often than the actual roster of who has weekly 1-on-1s changes, so a fixed list would drift.
- **Source material, newest-4 rule**: each note draws on up to the last 4 meetings, preferring already-processed `Transcripts/Done/` notes (richer, already synthesized) and falling back to a raw Google Drive transcript read directly wherever fewer than 4 processed notes exist yet - explicitly labeled per meeting which kind it is. For the owner's-own-manager case, "processed notes" means prior `Meeting Prep/Done/` notes from this same automation (the owner's own upward 1-on-1s aren't covered by the direct-report review pipeline), falling back to raw Drive transcripts the same way.
- **Three buckets, priority-sorted**: Follow-ups (recurrence-tagged, e.g. "3/4 meetings"), Growth, Achievements - each highest-priority-first, tagged inline (High/Medium/Low). See `Templates/Meeting Prep Template.md` for the exact note shape this task writes to.
- **One Slack message per run, not per person**: if 3 meetings qualify today, the owner gets a single combined summary rather than 3 separate pings.

## Why this is a separate task from direct-report-transcript-poll

The two run on different triggers (this one is calendar-driven, once a day; that one is transcript-driven, hourly during work hours) and write to different destinations (`Meeting Prep/` vs `Transcripts/`) with different purposes (prep for what's about to happen vs review of what already happened). Keeping them independent means either can be paused, edited, or re-scheduled without touching the other, and a slow review of one doesn't block the other from running.

## Companion command

`commands/meeting-prep-apply.md` - on demand, reads back a checked-off `Meeting Prep/To Review/` note, compiles the checked items into a talking-points-and-questions bullet list (the actual deliverable), moves the note to `Meeting Prep/Done/`, and confirms via Slack + push. Unlike `direct-report-apply-review-poll`, there is deliberately no hourly unattended poll counterpart yet for this apply step - the owner asks for it live (or runs `/meeting-prep-apply <Person>`) when they're ready, since the output is time-critical (needed right before a same-day meeting) rather than a background sync. Add an hourly poll later if that stops being fast enough in practice.
